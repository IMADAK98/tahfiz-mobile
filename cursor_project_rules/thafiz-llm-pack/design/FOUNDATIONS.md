# ثفيز — أسس التصميم (Design Foundations)

مسودات تصميم عربية RTL لإعادة كتابة لوحة إدارة Angular لنظام التحفيظ.

## 1. النطاق: إدارة المركز مقابل المعلم

| السطح | الجمهور | المسؤولية |
|---|---|---|
| **ويب — إدارة المركز** (هذه المسودات) | مشرف/مدير المركز | الإعداد، الموافقات، التقارير، القوائم، إنشاء الدورات والحلقات |
| **جوال — المعلم** | المعلّم | الحضور اليومي وتسجيل التقدّم — **لا تُصمَّم كشاشات ويب أساسية** |

- لا نسخ لنظام Focused؛ هوية ثفيز مستقلة (فيروزي + ذهبي خفيف).
- مستوحى من جرد الشاشات الحيّ، لكن بتجربة مستخدم جديدة (إصلاح فجوات: دخول عام، تسجيل مركز، لوحة مؤشرات).

## 2. المصادقة (Auth) — إلزامية لكل `/admin/*`

- **تسجيل الدخول مطلوب** لكل مسارات الإدارة `/admin/*`. الزائر غير المصادق يُوجَّه إلى `02-login.html` (أو مسار `/login`).
- الجلسة عبر **session cookie أو JWT** (يُحدَّد في التنفيذ Angular)؛ المسودات تفترض مستخدماً مصادقاً داخل الهيكل الإداري.
- لا واجهة إدارة «مفتوحة» أو ungated — فجوة Explorer الحيّ يجب ألا تتكرر في إعادة الكتابة.
- انظر أيضاً الملاحظة على `02-login.html` وشارة المصادقة على `03-dashboard.html`.

## 8. هيكل الإدارة (shell)

شريط جانبي يمين: نظرة عامة (لوحة التحكم) · التشغيل (حلقات، دورات) · الأشخاص (معلمون، طلاب، طلبات) · التقارير (حضور، تقدّم).  
CTA بارز: **إنشاء دورة** / **إنشاء حلقة**. تسجيل الحضور اليومي على الجوال فقط.  
**الهيكل بالكامل خلف المصادقة** (قسم 2).

### تفاصيل الحلقة (Ḥalaqa detail) — ضمن IA الإدارة
- من قائمة الحلقات يفتح **تفاصيل الحلقة** (ليست شاشة إدخال يومي للمعلّم).
- تبويب إلزامي في التفاصيل: **خطط الدراسة (Plans)** — عرض/تعيين خطط HIFZ · TATHBEET · MURAJAA للطلاب في الحلقة.
- تبويبات مقترحة: نظرة عامة · الطلاب · **الخطط** · (اختياري) ملخص تقارير قراءة فقط.
- تعيين طالب لخطة: إن كانت قائمة الطلاب المتاحين فارغة، أظهر حالة صريحة (انظر قسم 12) — لا منتقي صامت معطوب.
- **إضافة خطة** (من تفاصيل الحلقة): اسم الخطة · اختيار طلاب · بطاقات أنواع **حفظ / مراجعة / تثبيت** مع كمية/صفحة واتجاه (`عادي`/`عكس`) — مصدر حي: web-cases `01-ui-terms-halaqat-plans.md`.
- قائمة الحلقات النشطة تعرض بطاقات: فترة · معلّم · طلاب `N / limit` · حالة نشطة — **صنّف** المعنى (مسجّل / السعة) في إعادة التصميم.

## 11. روابط التسجيل (Registration URLs)

- استخدم **مضيف المنتج** أو placeholder موثّق — **ليس** hostname مفاجئاً من Vercel.
- مثال المسودات: `https://www.tahfiz.work/join/student/{token}` أو الشكل الموثّق `https://{app-host}/register/student/{token}`.
- Explorer الحيّ أظهر `tahfiz-client.vercel.app` كثيراً + UX نسخ متذبذب؛ إعادة كتابة Angular يجب أن تستخدم مضيف المنتج (يُقفل لاحقاً). المسودات تعرض نطاق المنتج فقط.
- UX النسخ: حقل رابط قابل للتحديد + زر **نسخ الرابط** واضح + تأكيد ثابت (toast «تم النسخ») — لا تعتمد على رسالة عابرة فقط أو hostname مفاجئ.

## 12. الحالات الفارغة (ومنتقيات الطلاب)

- حلقات: «لا توجد حلقات بعد» + إنشاء حلقة + تنبيه بإنشاء الدورة أولاً إن لزم.
- لوحة بلا دورة: ترحيب + KPI بصفر + CTA إنشاء أول دورة.
- لا تكرار مفرط لنفس CTA.

### منتقي الطلاب فارغ (إنشاء حلقة / تعيين لخطة)
Explorer: المنتقيات غالباً فارغة حتى بعد التسجيل إن وُجدت فجوة API (available vs active). في التصميم:
- لا تترك القائمة معطّلة بلا تفسير.
- انسخ واضح: **«لا يوجد طلاب متاحون للإضافة»** + سبب محتمل (غير مسجّلين في الدورة، أو مُضافون مسبقاً، أو استخدم قائمة الطلاب النشطين) + رابط لـ `10-students.html` / تسجيل طالب.
- نفس النمط عند **تعيين طالب لخطة** داخل تبويب الخطط.

### تقرير الحضور فارغ ≠ لا يوجد طلاب
- إن وُجد طلاب في الحلقة لكن لا سجلات للأسبوع/النطاق: **«لا علامات حضور بعد»** / «لم يُسجَّل حضور بعد في هذا النطاق» — وليس «لا يوجد طلاب».
- جدول أسبوعي فارغ: أعمدة الطلاب ظاهرة (إن عُرفوا) مع خلايا فارغة أو شرطة، ونص توضيحي أن الإدخال من تطبيق المعلّم.
- فقط عندما لا يوجد طلاب في الحلقة أصلاً: «لا يوجد طلاب في هذه الحلقة».

## 16. Web Explorer batch 1 — Terms / Ḥalaqāt / Plans (2026-09-10)

مصدر: `/workspace/thafiz-discovery/web-cases/01-ui-terms-halaqat-plans.md` + `01-terms-halaqat-plans.md` · ملخّص: `DISCOVERY-SUMMARY.md`.

### ما رأيناه في الحيّ (إلهام لا استنساخ)
- لوحة التحكم تعرض بطاقة الدورة النشطة `TEST-CoS-2026-09` (تواريخ + تسجيل + عطل) مع أيقونة تعديل؛ **لا عنصر «دورات» واضح في الشريط** ولا CTA إنشاء دورة عندما توجد دورة نشطة.
- قائمة الحلقات: بطاقات TEST 12 و 13 (فترة، معلّم، `N/حد`، نشطة).
- تفاصيل الحلقة: تبويبا **الطلاب** و **الخطط**؛ إضافة خطة / إضافة طلاب؛ صف خطة مع إضافة طلاب للخطة.
- مودال إضافة خطة: اسم · طلاب · أنواع حفظ/مراجعة/تثبيت مع كمية واتجاه.

### قواعد منتج من الـ API يجب أن تظهر في UX الإدارة
1. **دورة ACTIVE واحدة فقط لكل مركز** — `POST /term` → 400 *An active term already exists* حتى للدورة المستقبلية.
   - **قفل Imad 2026-09-10:** عند وجود دورة ACTIVE → **عطّل إنشاء دورة** + النص **«أنهِ الدورة الحالية أولاً»**. لا إنشاء حر ولا دورات INACTIVE مجدولة في المسودات حالياً.
2. منتقي الدورة في إنشاء الحلقة إلزامي (سبق توثيقه).
3. `available-students` غالباً فارغ بعد التسجيل — اعتمد طلاباً نشطين/مسجّلين في الدورة مع رسائل فارغة صريحة.

### ديون UX حيّة تُصلَح في Angular (لا تُنسَخ)
- إجراءات أيقونة فقط بلا اسم وصول (تعديل/حذف دورة/حلقة/خطة).
- تسمية سعة الطلاب `1 / 20` بلا تسمية أعمدة.
- إملاء `خطه` بدل `خطة` في مواضع.
- سلوك جلسة متذبذب (إعادة توجيه لـ login من بعض المسارات بينما صفحات أخرى ungated).


### ملاحظات API إضافية للتسليم Angular (Explorer feed)
- **Study plan:** `GET`/`PATCH` على `/study-plan/{id}` stubs بلا أثر — استخدم مسارات **`/details`** (وواجهات الإضافة من تفاصيل الحلقة) في العقود والتصميم.

- روابط التسجيل الحية ما زالت على **tahfiz-client.vercel.app** — المسودات تبقى على مضيف المنتج.

### اتجاه إنشاء الدورة — **مقفول**

- فرّق في UX: **مسجّل في الدورة** · **معيَّن لحلقة** · **طالب عائد يحتاج activate**.
